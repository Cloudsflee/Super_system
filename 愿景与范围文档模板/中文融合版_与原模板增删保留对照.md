# 中文融合版与两个原始模板的增删保留对照

> 对照对象：
>
> - `SoftwareReqs_KarlWiegers_Vision_and_Scope_Template.docx`
> - `UTSC_PMO_Simplified_Vision_and_Scope_Template.docx`

---

## 1. 总体结论

中文融合版采用了 **SoftwareReqs 模板作为主骨架**，再吸收 **UTSC 简化模板的“当前状态、范围内/范围外、数据考虑”表达方式**，最后补充了更适合毕业设计的内容。

一句话概括：

> 融合版 = SoftwareReqs 的完整需求工程结构 + UTSC 的简洁项目表达 + 针对你的毕设方向新增的评估、生态集成、数据与交付物章节。

## 3. 新增了哪些内容

融合版新增内容主要是为了适配你的毕设选题“面向超级个体的高效协作系统”。


| 新增内容      | 位置   | 新增理由                                              |
| --------- | ---- | ------------------------------------------------- |
| 模板来源说明    | 封面后  | 方便说明融合依据。                                         |
| 解决方案概述    | 2.1  | 原模板偏需求描述，融合版增加产品总体形态说明。                           |
| 目标用户与使用场景 | 2.2  | 你的系统用户类型复杂，包括超级个体、小团队、新成员、AI Agent 等。             |
| 核心能力      | 2.3  | 用来承接你的 8 条核心主旨。                                   |
| 与现有方案的差异  | 2.4  | 方便在论文/答辩中说明与 Notion、Linear、Logseq、Copilot 等工具的区别。 |
| 第一版范围     | 3.2  | 虽然 SoftwareReqs 有初始版本范围，但融合版明确改成毕设 MVP。           |
| 限制与约束     | 3.5  | 增加时间、人力、模型能力、API 成本、开源协议等毕设常见约束。                  |
| 生态集成考虑    | 4.5  | 对应你的“生态集成”核心主旨。                                   |
| 验收与评估     | 5    | 原始两个模板都没有独立验收评估章；毕设需要功能验收、非功能评估和演示依据。             |
| 功能验收标准    | 5.1  | 方便后续测试报告和答辩演示。                                    |
| 非功能需求评估   | 5.2  | 覆盖性能、可靠性、可维护性、可扩展性、安全性、可观测性等。                     |
| 毕设交付物     | 5.3  | 明确系统、文档、测试报告、论文、答辩材料等交付物。                         |
| 术语表       | 附录 A | 你的选题包含“超级个体、行为资产化、重构成本定量化”等自定义概念，建议解释。            |
| 待确认问题     | 附录 B | 便于后续和导师沟通、收敛范围。                                   |

## 4. 删除或弱化了哪些内容


| 原模板内容                      | 处理方式           | 原因                                      |
| -------------------------- | -------------- | --------------------------------------- |
| 原英文目录页码                    | 删除/不保留         | Markdown/中文模板不需要固定页码，Word 可自动生成目录。      |
| SoftwareReqs 中较长的英文填写说明    | 改写为较短中文填写提示    | 避免模板太长，降低填写负担。                          |
| SoftwareReqs 的问题陈述固定句式     | 弱化为“业务问题或机会”表格 | 毕设中更适合用表格描述痛点、影响和改进。                    |
| SoftwareReqs 的愿景声明英文句式     | 保留为中文填写提示      | 不逐字照搬，避免表达生硬。                           |
| SoftwareReqs 的利益相关者价值示例长列表 | 没有完整放入融合版      | 融合版改为直接填写利益相关者表，保持简洁。                   |
| SoftwareReqs 的项目优先级示例值     | 删除示例值，仅保留维度    | 示例中的日期、团队规模、预算与毕设无关。                    |
| UTSC 的利益相关者示例角色            | 删除示例行          | executives/editors/legal aides 与你的项目无关。 |
| UTSC 中 UofT 系统集成示例         | 泛化为数据与第三方集成    | 你的项目不一定与 UofT 系统有关。                     |
| Microsoft MOF 模板相关内容       | 不纳入融合版         | 你已决定只保留两个核心模板；MOF 偏企业 IT 部署，过重。         |

## 6. 对你的毕设的保留建议

建议保留：

1. `1.4 成功指标`：答辩时很有用。
2. `2.3 核心能力`：直接承接你的 8 条主旨。
3. `3.2 第一版范围` 和 `3.4 范围外内容`：防止范围过大。
4. `4.3 数据考虑`：你的系统涉及行为日志、AI 调用、贡献量化，必须说明数据问题。
5. `4.5 生态集成考虑`：对应你的开发侧主旨。
6. `5. 验收与评估`：毕业设计比普通产品文档更需要验收依据。
7. `附录 A 术语表`：你的概念比较新，建议保留。

如果后续想压缩篇幅，可以考虑删减：

1. `2.4 与现有方案的差异`：如果论文已有相关工作章节，可合并过去。
2. `3.3 后续版本范围`：如果导师要求文档短，可以简写。
3. `附录 B 待确认问题`：正式提交版可以删除，只在草稿阶段保留。
