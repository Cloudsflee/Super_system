# 03. 可落地模型草案

> 生成时间：2026-07-07  
> 目的：把“Workspace 记忆 + Context Pack + Codex/Runner 核心”从概念推向可实现的数据模型、交互流程和 MVP。

---

## 1. 核心对象关系

```text
Project
  └── Workspace
        ├── WorkspaceDigest[]
        ├── ContextPack[]
        ├── WorkThread[]
        ├── AgentSession[]
        ├── AssetRef[]
        ├── TraceEvent[]
        └── DecisionRecord[]
```

Workspace 可以是：

- Project Workspace；
- Node Workspace；
- Sub Workspace。

WorkThread 是最小协作单位。

---

## 4. WorkspaceDigest Schema 草案

```ts
type WorkspaceDigest = {
  id: string
  workspace_id: string
  version: number

  goal: string
  status: string

  current_conclusion: string[]
  confirmed_facts: string[]
  hypotheses: string[]
  risks: string[]
  blockers: string[]
  next_actions: string[]

  output_asset_refs: AssetRef[]
  evidence_refs: AssetRef[]
  decision_refs: DecisionRef[]
  open_questions: string[]

  confidence: 'low' | 'medium' | 'high'
  generated_from_trace_refs: TraceRef[]
  generated_by: ActorRef
  confirmed_by?: ActorRef

  created_at: string
}
```

设计重点：

- Digest 要版本化；
- Digest 不是最终真理；
- Digest 可以是 AI 草稿，也可以被用户确认；
- 父 Workspace 默认读取子 Workspace 最新 Digest。

## 9. Context Pack 生成算法草案

```text
输入：
  workspace_id
  receiver
  purpose
  expected_outputs

步骤：
  1. 读取 Workspace 当前目标和状态
  2. 读取当前 Workspace Digest
  3. 读取父 Workspace Digest
  4. 根据 purpose 选择相关资产
  5. 根据 receiver 能力裁剪上下文
  6. 加入约束和验收标准
  7. 加入可用工具和权限
  8. 生成结构化 Context Pack
  9. 保存 Context Pack 版本
  10. 发送给 Runner / Workspace / 插件
```

## 10. 交互流程：节点工作空间启动 Codex

```text
用户进入 Node Workspace
  → 系统展示当前 Digest
  → 用户点击“启动 AI 协作”
  → 系统询问目的：分析 / 编码 / 评审 / 总结 / 自定义
  → Context Pack Builder 生成上下文包
  → 用户可预览关键上下文
  → 启动 Codex Session
  → Codex 执行任务
  → 系统记录 Trace
  → Result Normalizer 归一化结果
  → 生成资产候选 / 决策候选 / 问题列表
  → 用户确认
  → Workspace Digest 更新
```

---

## 11. 交互流程：父 Workspace 查看子 Workspace

```text
父 Workspace 页面
  → 子空间卡片列表
      - 标题
      - 状态
      - 一句话结论
      - 风险/阻塞
      - 下一步
  → 点击展开
      - 查看 Workspace Digest
  → 继续展开
      - 查看资产和证据
  → 继续展开
      - 查看关键过程记录
  → 高级展开
      - 查看原始 Trace
```

默认不加载全量 Trace。

---

## 12. 交互流程：子 Workspace 请求父空间上下文

```text
子 Workspace 需要父空间信息
  → 请求 parent_digest
  → 如果不够，选择需要的资产/决策/Trace
  → 父空间生成 Context Pack
  → 子空间读取 Context Pack
  → 子空间继续执行
```

## 15. 评价指标

| 指标 | 如何观察 |
|---|---|
| 上下文是否足够 | AI 是否能完成任务，是否频繁问已知信息。 |
| 上下文是否过载 | Context Pack 是否太长、噪声太多。 |
| 父空间是否理解子空间 | 只看 Digest 是否能理解状态和风险。 |
| 可追溯性 | Digest 是否能追溯到资产和 Trace。 |
| 可替换性 | 同一 Context Pack 是否能给 Codex / Claude Code 使用。 |
| 用户控制感 | 用户是否能预览和调整 Context Pack。 |
| 复盘价值 | 过程结束后是否能沉淀为资产。 |

## 16. 当前最小闭环

```text
Workspace 目标
  → 生成 Context Pack
  → Codex Runner 执行
  → Result Normalizer 收结果
  → Trace Recorder 记录过程
  → Asset Extractor 生成资产候选
  → 用户确认
  → Workspace Digest 更新
  → 父 Workspace 消费 Digest
```

这个闭环如果能跑通，就已经能体现系统核心价值。
