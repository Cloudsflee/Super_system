# V3 功能恢复测试计划

## 治理测试 T0

- `pnpm recovery:plan`：检查两份计划、领域覆盖和目录数量。
- `pnpm recovery:catalog`：检查 ID 唯一性、必需字段、状态枚举和旧 runtime 隔离。
- `pnpm recovery:coverage`：检查每项功能至少映射一个 T0-T8 闸门，显式测试文件必须存在。
- `pnpm recovery:impact --audit`：读取 staged、unstaged、untracked 文件，输出受影响功能和测试；未映射源码在 audit 模式失败。

## T1 Schema 与回滚

空库必须创建 V3 strict schema、索引、外键和不可变触发器；事务失败必须回滚。重启后 `integrity_check=ok` 且 user version 不变。迁移或恢复只能使用临时数据库和临时卷；V2.3 归档只读，正式卷不打开、不写入、不锁定。

## T2 Secret、Setup 与 Probe

覆盖合法、空、损坏、model 不一致、超时和强制 Probe。凭据明文不得进入 SQLite、日志、SSE、HTTP error、Broker 状态、CAS 或 Evidence。GitHub 覆盖 token/JWT 配置、仓库发现、权限失败和 webhook HMAC。

## T3 Runner、Broker 与 MCP

覆盖 Job Spec 白名单、digest、deadline、resource、network、HMAC 过期/重放、Docker 参数边界、cancel/timeout/crash/retry 和临时凭据清理。REST 与 MCP 必须调用同一 command registry，并保持结果、幂等和 audit 等价。

## T4 Project、Workflow、DAG 与 Outcome

覆盖 Project/Brief revision、两级 DAG、循环/反向依赖、重复输出、路径冲突、并发 revision race、execution start/cancel/recovery、人工 checkpoint、stage replay、Outcome rubric、waiver 和 release eligibility。

## T5 Assist、Files、Attachment、Terminal 与 Approval

覆盖四层 scope snapshot、turn lifecycle、Goal/Plan、SSE replay、MIME/SHA/配额/安全预览、Change Batch、stale protection、apply/rollback、Terminal approval、真实 PTY、WebSocket reconnect/cursor replay、SIGINT、resize、stop、orphan recovery、跨 chunk 脱敏、CAS terminal artifact、Git bundle SHA/ref/path 校验，以及 Runtime Approval 和 user-input resume。

## T6 Context、Evidence 与 Quality

覆盖 Context map/search/read/selection/policy/rebuild、projection crash recovery、Context Pack hash、Asset CAS/Relation/Trace/Digest/Attestation、Evidence capture retry/discard、secret-output rejection、parser isolation、freshness 和固定 80 分人工阈值。不支持的音视频、PPTX 和压缩包必须返回稳定错误。

## T7 Repository 与 GitHub Delivery

覆盖 binding/worktree fault state、project/delivery branch 幂等、patch SHA、node test、git diff check、Draft PR 去重、expected head SHA、merge race、branch delete、本地 fast-forward 和 429/502/timeout retry。真实 fixture 仅使用空仓库。

## T8 Browser、性能与发布

浏览器验收至少包含 `1440x900`、`1024x768`、`390x844`，并检查 page error、console error、布局重叠和 SSE reconnect。故障测试覆盖 Broker/Runner/parser/SQLite worker 中断。发布演练必须使用 digest-pinned image、临时卷、动态端口、hash restore 和可执行 rollback。

## 固定执行顺序

```text
pnpm recovery:plan
pnpm recovery:catalog
pnpm recovery:coverage
pnpm recovery:impact --audit
pnpm check
pnpm test
pnpm test:integration
pnpm test:security
pnpm test:e2e
pnpm test:release
pnpm verify
```

任何命令失败时对应功能保持 incomplete；真实 Runner/GitHub capability 缺失时仅记录 candidate，不进入正式发布。
