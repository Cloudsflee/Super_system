# AIWS V1.7 Cutover

## 固定目标

- Compose project：`aiws-v17`
- App：`aiws-app:1.7.0`
- Verify：`aiws-verify:1.7.0`
- Runner：`aiws-codex-runner:1.7.0-codex-0.144.0`
- 只读源卷：`aiws-data-v16` / schema 15
- 正式目标卷：`aiws-data-v17` / schema 16

## 切换

1. 执行完整 lint、typecheck、test、integration、E2E、build 与 `test:release`。
2. 记录 `aiws-data-v16` state SHA-256、canonical hash、集合计数和文件清单。
3. 运行 `scripts/aiws.ps1 up` 或 `scripts/aiws.sh up`。脚本停止 V1.6 app，将源卷只读挂载并归档到临时迁移卷，再解压到空目标卷。
4. V1.7 App 首次打开目标卷时执行 schema 15→16 原子迁移；迁移 manifest 必须为 committed。
5. 发布脚本验证源卷未变化、旧记录 ID 未丢失、非迁移文件未变化、官方 Runner 引用已更新。
6. `http://127.0.0.1:4317/api/health` 必须返回 `status=ok`、`version=1.7.0`、`schema_version=16`。

## 回滚

迁移、容器、健康或验收任一步失败时：

1. 停止并移除 V1.7 Compose app，不删除 `aiws-data-v17` 以便诊断。
2. 重启切换前记录的 V1.6 容器。
3. 复核 `aiws-data-v16` state SHA-256 与切换前一致。
4. 不执行空白启动，不自动删除 V1.6 卷或镜像。

## 后续清理

只有 V1.7 验收完成后才可单独执行 `purge-legacy --confirm`。清理前必须再次验证 V1.7 健康状态、schema 16、迁移 receipt、源记录 ID 保存关系和无旧 Runner 引用。
