# AIWS V1.8 Cutover

## 固定发布对象

- Compose project：`aiws-v18`
- App：`aiws-app:1.8.0`
- Verify：`aiws-verify:1.8.0`
- Runner：`aiws-codex-runner:1.8.0-codex-0.144.0`
- 只读源卷：`aiws-data-v17` / schema 16
- 正式目标卷：`aiws-data-v18` / schema 17

## 切换

1. 执行 `scripts/aiws.ps1 verify` 或 `scripts/aiws.sh verify`。
2. 执行 `up`。目标卷非空时只复用，不重新克隆。
3. 首次升级从只读 `aiws-data-v17` 创建归档，在临时迁移卷中校验，再解压到空目标卷。
4. App 启动时原子执行 schema 16→17，创建空 `mcp_clients`，写入 migration manifest；失败自动恢复原 state。
5. release acceptance 比较源/目标 inventory、record IDs、schema manifest 与源 state SHA-256。
6. `/api/health` 必须返回 `version=1.8.0`、`schema_version=17`；随后执行 Codex reprobe。

## 回滚

升级失败时 orchestrator 停止 V1.8、保留源卷/目标卷/迁移卷和 transcript，并恢复切换前停止的 V1.7 容器。`aiws-data-v17` 始终只读挂载，失败前后的 state SHA-256 必须一致。

## 清理

只有 V1.8 acceptance 完成后才可执行 `purge-legacy --confirm`。清理前再次验证正式 image、Compose project、schema 17 receipt 和不存在旧 Runner 引用。`down` 不删除 `aiws-data-v18`；`reset --confirm` 才允许删除正式卷。
