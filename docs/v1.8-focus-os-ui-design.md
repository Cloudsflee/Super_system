# AI Workspace V1.8 Focus OS UI 设计规范

## 1. 文档状态

- 状态：已实现，作为后续 UI 迭代与回归测试的基线。
- UI 里程碑：V1.8 Focus OS。
- 产品运行版本：`1.8.0`。
- 持久化 schema：继续使用 `16`。
- 约束：不新增服务端 API，不改变 Assist、Workflow Change Proposal、镜像或数据卷协议。

V1.8 只重构工作方式和视觉层级。所有工作流结构编辑仍先形成 Change Proposal，审批前不得改变正式图；Assist 继续使用 V1.7 的线程、Turn、Goal、EventSource 和操作回执协议。

## 2. 设计目标

Focus OS 面向需要长时间查看工作流、频繁切换节点上下文并持续与 Assist 协作的用户。界面优先保证：

1. 工作流始终是主画布，浮层不得压缩或重排画布。
2. Inspector 与 Assist 共享一条上下文轨道，最后一次显式操作决定当前任务。
3. 常用操作一步可达，低频操作收进菜单，危险写入继续经过 Proposal 或显式确认。
4. 桌面端支持并行观察，移动端一次只呈现一个完整任务。
5. 文档型页面保持安静、可读的中性浅色，深色只用于沉浸工作空间及其协作浮层。

非目标包括品牌迁移、后端协议升级、状态 schema 升级以及用新组件绕过现有治理流程。

## 3. 视觉系统

### 3.1 双表面模型

- Document：Setup、Onboarding、设置、列表和文档编辑区，使用中性浅色。
- Workspace：Workflow Canvas、Assist、Command Dock、Inspector、菜单和相关浮层，使用 Graphite 深色。

深色不是全局主题开关。路由语义决定表面，确保设置与文档阅读不会被画布主题污染。

### 3.2 核心变量

```css
--document-bg: #f6f7f9;
--document-surface: #fbfcfd;
--document-raised: #eef1f4;
--workspace-bg: #111315;
--workspace-surface: #1a1d20;
--workspace-raised: #22262a;
--workspace-text: #f3f5f7;
--workspace-muted: #9aa3ab;
--workspace-line: rgba(255, 255, 255, 0.09);
--accent: #16805f;
--accent-bright: #63d6a6;
--radius-container: 8px;
--radius-control: 6px;
--shadow-ambient: 0 24px 72px rgba(0, 0, 0, 0.38);
```

普通按钮和内容块不使用投影。Ambient Shadow 只用于需要与画布分层的浮动 HUD、Overlay、菜单和 Command Dock。字体大小固定，不随视口宽度缩放；字距为 `0`。

## 4. 工作流 Shell

### 4.1 Control Island

- 工作流路由使用全视口画布，`.route-stage` 始终保持 `100%` 宽高。
- 顶栏成为距视口 12px、40px 高的浮动 Control Island。
- 专注模式默认开启，仅保留导航、工作流名称、审批、Assist 和退出专注入口。
- 普通模式恢复品牌、项目选择和完整位置信息。
- `focusMode` 按浏览器持久化；首次访问或旧状态缺少该字段时默认 `true`。

### 4.2 Canvas HUD

- 编辑 HUD：添加节点、AI 生成、专注模式和更多菜单。
- 更多菜单：模板、自动布局、撤销、重做。
- 视图 HUD：放大、缩小、适配视图。
- 画布中心不显示标题胶囊；语义标题保留为屏幕阅读器可访问的 `h1`。
- MiniMap 在专注模式隐藏，普通模式恢复。
- 画布缩放范围为 `0.25` 到 `1.8`；700px 以下首次适配的最小缩放为 `0.78`，并允许平移。

## 5. Task Card

- 固定尺寸 `248 x 156px`，容器圆角 `8px`。
- 信息顺序：节点类型与状态、标题、最多两行目标、最近运行/输出/待审批指标。
- 状态文案统一为“就绪、执行中、已完成、已阻塞、失败”。
- `running` 使用 1px 品牌描边和低强度发光；选中态使用独立外轮廓，二者不得共用同一视觉信号。
- Hover 或 `:focus-within` 显示“进入工作区、让 Assist 优化、更多”图标；移动端只常驻“更多”。
- 右键、`Shift+F10` 和省略号使用同一 `ContextMenuProvider` 动作源：查看详情、进入工作区、让 Assist 优化、编辑节点、移除节点。
- 菜单关闭后焦点回到触发元素。编辑和移除只创建 Change Proposal，不能直接修改正式工作流。

## 6. 单一上下文轨道

`contextLane` 只有 `assist`、`inspector` 和 `null` 三种非持久化状态：

| 显式操作 | 展开对象 | 保留对象 |
| --- | --- | --- |
| 选择节点 | Inspector | 已存在的 Assist 会话保持可恢复 |
| 打开 Assist | Assist Overlay | 已选节点变为 Inspector Peek |
| 点击 Inspector Peek | Inspector | Assist 保持可恢复 |
| 收起 Assist | Inspector（若有已选节点） | Assist 回到 Command Dock |
| 关闭 Inspector | 无或 Assist | 节点选择清除 |

Node Inspector 头部只保留“进入工作区”和“更多”。编辑表单内部显示取消与提交提案；桌面端为右侧 Overlay，700px 以下为全屏单任务层。

## 7. Assist 与 Command Dock

### 7.1 单一控制器

`AssistCenter` 位于 AppShell 层，只创建一个 `useAssistController`。Command Dock 与 Assist Workbench 通过 Context 共享：

- 当前线程与线程列表；
- prompt、附件、Plan 和模型配置；
- queue、steer、interrupt 状态；
- 同一 EventSource 生命周期。

任何子表面不得自行创建第二个 controller 或 EventSource。

### 7.2 Command Dock

- 所有 `/projects/:projectId/*` 页面底部显示直接可输入的 Dock。
- 无线程时首次发送先创建当前项目或节点作用域线程，再提交同一 Turn。
- 发送后立即展开 Assist；失败时保留 prompt、附件和本次 Plan 状态，并使用 Toast 报错。
- 只读原因使用 `LockKeyhole` 状态行，不禁用普通聊天或 Plan。
- 非画布项目页为 Dock 预留底部安全区，Toast 也必须避让 Dock。

### 7.3 Assist Surface

- `docked`：右侧 Overlay，距视口 12px，默认宽 `520px`，允许 `420-680px`。
- `floating`：可移动浮窗。
- `fullscreen`：全视口工作区。
- `minimized`：不显示 Workbench，回到 Command Dock；恢复时使用上次非 minimized 模式。
- 旧持久化宽度必须安全夹紧到当前范围。
- 线程列表是覆盖对话的临时面板，不永久切分主内容。

### 7.4 对话与回执

- 用户消息使用低饱和灰色气泡；助手回复使用无容器的文字流。
- Goal 是置顶细行；Runtime 和 token 事件默认折叠。
- 普通 OperationReceipt 的定位、直接编辑、继续修改和撤销进入菜单。
- 待确认操作继续显式显示拒绝/确认；提案回执显式显示“审查提案”；冲突处理保持可见。
- 机器工具名和内部 lifecycle 状态不得泄露到用户文案。

## 8. 响应式与无障碍

- `> 700px`：Assist 和 Inspector 使用右侧 Overlay，并通过 Peek 恢复另一上下文。
- `<= 700px`：Assist、Inspector 和审批为全屏单任务层；不依赖 Hover；线程列表与对话互斥显示。
- Onboarding 在 850px 下改为单列；620px 下隐藏步骤文字并使用图标进度。
- Onboarding Header 约 64px，步骤轨道 36px，步骤间不使用竖线或大圆节点。
- 所有图标按钮必须提供可访问名称；未知图标通过 Tooltip 命名。
- 菜单支持键盘导航、Escape 关闭和焦点恢复；原生菜单可通过 `Shift + 右键` 绕过。
- 所有动画遵守 `prefers-reduced-motion`。
- 固定格式控件使用稳定尺寸，任何视口不得横向溢出或出现控件重叠。

### 8.1 浮层层级

交互层级从低到高依次为工作区内容、Command Dock、Assist/Inspector、Scrim、Nav/Approval Center、即时 Approval Prompt、Toast、上下文菜单与附件预览。Nav 或 Approval Center 打开时，Scrim 必须位于 Dock、Assist 和 Inspector 之上，禁止背景控件截获点击；即时审批必须高于普通抽屉，但允许与画布 Inspector 保持可见的上下文关系。

## 9. 客户端状态边界

持久化字段：`activeProjectId`、Assist surface/restore surface、浮窗 geometry、dock width、`focusMode`。

非持久化字段：Assist 是否展开、`contextLane`、Inspector 节点与模式、审批浮层、Toast。页面刷新后不得恢复一个遮挡内容的临时 Overlay。

离开 `/projects/:projectId/workflow` 时必须清除 Inspector 选择与 `contextNodeId`。节点工作区可通过路由参数重新建立节点作用域，不能继承已卸载画布的 `contextLane`，否则移动端会错误隐藏 Command Dock。

当前 localStorage store 名继续使用 `aiws-v13-ui` 以兼容既有数据；store version 为 `18`，迁移与 merge 必须为缺失字段提供安全默认值。

## 11. 验收基线

每次修改上述交互或样式后至少执行：

```bash
corepack pnpm lint
corepack pnpm typecheck
corepack pnpm test
corepack pnpm build
node tests/integration/v17-workflow-assist-flow.test.mjs
node tests/e2e/playwright.test.mjs
```

Playwright 基准视口为 `1728x1117`、`1440x900`、`1024x768` 和 `390x844`。必须断言 Overlay 不压缩画布、无横向溢出、移动端无需 Hover、Toast/审批不遮挡 Dock、审批前工作流图不变，并保留节点 Hover、菜单、Inspector、Assist 与回执截图。

Nav Drawer 与 Approval Center 还必须在四种视口中阻断 Command Dock 的指针命中，确保视觉前景与实际交互前景一致。
