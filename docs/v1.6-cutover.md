|---|---|

首次 `up` 只在目标卷不存在或为空时迁移。源卷以只读 mount 归档到带 `aiws.owner=aiws-v16-release` 和 `aiws.role=migration` 标签的临时卷，归档通过严格 validator 后才解压到目标。`codex-homes/*/tmp` 不迁移；其他文件、相对安全符号链接、集合数量和记录 ID 必须通过结构化验收。

schema 迁移只把固定格式的 V1.0-V1.5 官方 Runner 标签改为 V1.6，并将对应 Profile Probe 标记为 stale。自定义镜像、Endpoint、凭据引用和其他 Profile 字段保持不变。

## 失败策略

- 默认：停止失败的 V1.6，保留只读源、失败目标和临时迁移卷，并恢复切换前运行的 V1.5/preview 容器。
- 显式丢弃：只有 `-DiscardUnmigratable` / `--discard-unmigratable` 会删除失败目标卷，创建空 `aiws-data-v16` 并启动全新 schema 15。
- 外部 Probe 失败：记录为 Setup 降级，不回滚或删除已迁移数据。
- 重复 `up`：复用非空目标卷并校验既有迁移凭据，不重新克隆源卷。

## 清理边界

`purge-legacy` 必须显式确认，并在清理前验证正式容器身份和 health、目标 schema、带 SHA-256 的迁移验收凭据及零旧 Runner 引用。允许删除的资源只有：

- Compose project `aiws-v14`、`aiws-v15`、`aiws-v16-preview` 的容器和网络；
- `aiws-data-v14`、`aiws-v16-preview-data` 和本次带标签的临时迁移卷；
- V1.4/V1.5 app、verify、Runner 镜像及 `aiws-codex-runner:local`；
- `.ai-workspace/backups` 全部内容；
- 目标卷 `data/migrations` 中旧 schema 的 state 备份 JSON，迁移 manifest 保留。

清理不会扫描或删除无归属匿名卷，也不会操作 Opsbot、DotAI、Langfuse。清理完成后旧数据不可恢复。
